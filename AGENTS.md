# AGENTS.md

This file provides guidance to coding agents when working with code in this repository.

## Commands

```bash
bun install          # Install dependencies
bun run dev          # Start local development server
bun run check        # Astro diagnostics, then generate Worker types and type-check worker/
bun run test         # Worker unit tests (bun test)
bun run lint         # Lint Astro, TypeScript, and JavaScript
bun run build        # Production build
bun run preview      # Preview build locally via Wrangler
bun run deploy       # Build and deploy to Cloudflare Workers
```

## Architecture

Personal site built with Astro, deployed as static assets on Cloudflare Workers. One dark, narrow column (39rem): a photo pile, short first-person intro, experience, side projects, writing and talks, contact, and a flower garland above the footer. Zero framework JavaScript.

### Tech Stack
- **Astro 7** - Static site generator with `output: 'static'`
- **TypeScript** - Strict mode via Astro's tsconfig. Stays on TypeScript 6: `astro check` does not support 7, and its replacement (`@astrojs/ts-content-mapper`) needs 7.1+. `@astrojs/check` stays on 0.9.10 with `@astrojs/language-server` 2.16 (held by `bun.lock`): language server 2.17 switched to the `astro2tsx` parser, which reads the `/` in `x! / y` (a non-null assertion before a division, as in `AsciiGarland.astro`) as a regex and loses the frontmatter. Still broken in `@astrojs/astro2tsx` 0.1.4 (November 2026); retry the upgrade when a later release fixes it
- **Astro Content Collections** - Typed Markdown-backed work, project, and speaking entries with `image()` icons
- **astro:assets** - App icons and photos are optimized at build time (1x/2x/3x webp)
- **Cloudflare Workers Assets** - Hosting via Wrangler asset deployment, configured in `wrangler.jsonc`; Wrangler is pinned exactly (dependencies can be newer than bun's 7-day minimum age: Ertem allows `bun add --minimum-release-age=0` for packages from their official publishers). **Planned: move to `cloudflare.config.ts` once it is stable.** Checked in November 2026: the path is `cf migrate --bundler vite` plus `@astrojs/cloudflare` 15, the first adapter that reads `cloudflare.config.ts` (it keeps a user `worker.entrypoint`, so `worker/index.ts` stays the entry and pages stay prerendered). Today `cf`, the config format, the Cloudflare Vite plugin 2.0 it needs, and adapter 15 are all beta, and `cf build` cannot take a static `dist/` without the adapter. Migrate when they are stable, then switch the Workers Builds commands from Wrangler to `cf deploy` and `cf previews deploy`, and the scripts to `cf dev`, `cf build` and `cf workers types`
- **CI and deploys** - GitHub Actions (`.github/workflows/ci.yml`) runs `check`, `test`, `lint` and `build` on every pull request and push to `main`; Workers Builds deploys (`main` to production, other branches to preview URLs). `packageManager` in `package.json` pins Bun and `.node-version` pins Node for both
- **Inter Variable + Geist Mono Variable** - Self-hosted in `src/assets/fonts/`, preloaded, `font-display: block`. They are the fontsource Latin files with the weight axis trimmed to the 400–700 the CSS uses (every glyph and OpenType feature kept; checked to wrap every page identically): `uvx --from 'fonttools[woff]' fonttools varLib.instancer <font>.woff2 wght=400:700 --no-optimize -o out.ttf`, then `uvx --from 'fonttools[woff]' pyftsubset out.ttf --unicodes='*' --layout-features='*' --name-IDs='*' --notdef-outline --flavor=woff2`. Geist Mono's preload is low priority because mono only appears below the fold

### Content Structure
- `src/data/site.ts` - Profile copy, the intro (written once: strings plus `{ work }` references that the hero renders as morphing app chips and the Markdown twins as links), `current` (the work entry the intro and the home page's JSON-LD point at), links, external writing, and the Connect row (inline Simple Icons glyph paths)
- `src/data/entries.ts` - The one place that loads and orders the collections (`loadEntries()`), builds the detail routes (`entryPaths()`), entry URLs (`entryUrl()`), and the date and meta lines (`when()`, `metaLine()`, exhaustive over `entry.collection`)
- `src/content/work/*.md` - Work experience entries (`role`, `period`, optional `icon`)
- `src/content/projects/*.md` - Side project entries (`year`, `icon`)
- `src/content/speaking/*.md` - Talks (`event`, `year`, `icon`)
- Every entry has `links` (first one is the primary chip on its detail page) and optional `screens` (app screenshots rendered in iPhone frames); keep link lists out of Markdown bodies
- `src/assets/me/` - Photos and clips for the hero pile, sorted by filename
- `src/content.config.ts` - Schemas and glob loaders for all collections
- `src/assets/icons/` - App icons and company logos referenced from frontmatter
- `src/assets/og-card.png` - The 1200×630 social card (photo pile, name and the garland), a screenshot of the live page composed at that size; `Layout.astro` imports it with `?url`, so a new card gets a new hashed URL and link previews pick it up
- Dynamic routes use `getStaticPaths()` and `render()` for static generation

### Data Flow
1. Pages and the Markdown endpoints load entries through `src/data/entries.ts`, never `getCollection()` directly
2. Collection frontmatter supplies summaries, icons, and metadata for the index
3. Markdown bodies render only on detail pages through the shared dynamic route
4. Site-wide profile, intro and writing data comes from `src/data/site.ts`; the HTML and its Markdown twin render the same values

### Key Components
- **AppIcon.astro** - Renders an image inside an Apple-style squircle (an SVG mask, so every browser clips the same shape) and either a static `view-transition-name` (detail pages) or a `data-morph` candidate (the index)
- **IconTile.astro** - Monochrome glyph in a squircle tile with a hover tooltip, used for the Connect row
- **PhotoStack.astro** - The hero pile of photos/videos. A mouse hover (fine pointers) or a tap opens it into an orb around the top photo: the ring follows the pointer, or spins when dragged on touch, and a picked card swaps places with the top photo. The ring shares its places evenly among the cards other than the top one, and the pile opens in one move. A click on the top card, or a sideways swipe on touch, sends it to the back: a pressed card shrinks at once, a swiped one follows the finger 1:1 for a quarter of its width and then rubber-bands against its own width (so it never travels much past one card), and letting go in the stretch, or flicking so it would coast into it (UIScrollView's deceleration projection), sends it to the back, while a small drag that stays in the free stretch springs home. Every move is a spring, with a little bounce only after a throw; reduced motion keeps the orb off
- **AsciiGarland.astro** - The flower garland above the footer. `src/assets/garland.svg` (a painted illustration, edit it to change the art) is rasterised with sharp at build time and turned into coloured characters: one glyph per 8×13 px cell from coverage, light and edges; colours lifted in OKLCH, snapped to a 48-tone k-means palette and written in Display P3 (also emitted per tone in `data-tones`). It sits one section gap below the last section, its six rows of sky rising into that gap, with its ground running straight into the footer (no rule between them) (`-webkit-text-size-adjust: 100%` on `html` keeps iPhone Safari from inflating its 4px glyphs, which threw the layout off; it stands alone because the CSS minifier drops a prefixed declaration that sits beside its unprefixed twin, and Safari reads only the prefixed one). It runs full bleed: the painting tiles seamlessly (flower heads stay clear of the seam) and repeats across any width. The script finds each flower (connected same-hue patches) and draws everything with WebGL 2: every glyph is one instance of a quad over a white glyph atlas, the vertex shader moves it by its plant's bend or the wave field from a small float texture, a second instanced pass with a blurred atlas adds the glow, flower heads paint an opaque cell behind themselves (back-to-front order) and the edge fade is done in the shader. Physics: each stem is a cantilever rooted at the ground under a heavy head, drawn in the beam's exact shape for the loads on it, with the head riding the tip as one piece; the head swings with inertia toward a 1D wave field driven by a breeze and rolling gusts. The hand is a soft spring rather than a wall: a touched point gives part of the way, so a slow push bends a flower (pushed low, the head swings further), and a fast swipe, which can cross a stem between pointer events, flicks whatever its path runs through toward its own speed; a stem the hand slips off springs back, leaves follow the field, the pointer or a finger pushes plants aside and stirs the field, and bees (about one per 90 columns in view, flying across the whole width rather than repeating with the painting, each on a flower of its own) hover between flowers, and butterflies (about one per 160 columns, `\i/` over `/'\` wings that fold through `| |` to `' '`) each in a random sky blue, white, lemon or lilac, drift between the tall flowers in bursts of bobbing wingbeats and short glides on open wings, land on a head and ride it as it sways, and fly off when a hand comes near. Untouched it draws from a timer at about 24fps; after 8s without scrolling, pointer or keys the breeze dies down, the bees land and drawing stops (0% CPU) until something moves. WebGL starts only once the garland comes within half a window of view (setup is the page's heaviest work, and over a second where WebGL runs in software, as on PageSpeed Insights' test devices); until then the static art shows, its `<pre>` `inert` so it is pure decoration to assistive tech and to Lighthouse's contrast check. Setup reads the art back in one task and builds the WebGL scene in the next (the canvas goes in and draws its first frame in the same task), so neither holds up input for long. Without WebGL 2 or with reduced motion the static art shows
- **Layout.astro** - Metadata, font preloads, the once-per-session intro flag, optional JSON-LD (`jsonLd`), `notFound` for the 404 (no canonical, no Markdown twin, `noindex`), and the Cloudflare Web Analytics beacon (production builds only; in the head, which page swaps keep, so it loads once and reports each swap itself)

### Styling and motion
- Global styles and CSS variables live in `src/styles/globals.css`
- Dark-only theme, `#0a0a0a` background
- `<ClientRouter />` (astro:transitions) swaps pages in place, so view transitions run without a document reload; an entry's icon and title morph into the detail heading via `icon-<id>` / `title-<id>` names. Detail pages carry them statically; on the index several links can point at one entry (the intro sentence and its row), so candidates are marked with `data-morph` inside an `a[data-morph-scope]` and `src/scripts/navigation.ts` (loaded by `Layout.astro`) assigns the names at navigation time to the link that was used, and restores them on that same link when coming back. Scripts bind on `astro:page-load`
- Page transitions: both pages fade on one curve (240ms), so together they never dip to black; icons and titles travel 350ms on `--ease-ios` (the iOS drawer curve), and their own two snapshots cross-fade in 200ms on `--ease-out` so they never ghost for long. Browsers morph a group by animating its width and height on the main thread, so `navigation.ts` swaps each group animation for an equivalent compositor-only scale. iPhone Safari paints the page under its status bar and toolbar, outside the viewport a page snapshot covers, so there the root takes no snapshot (`@supports (-webkit-touch-callout: none)`) and the live pages cross-fade instead: before the swap `navigation.ts` moves the old page's nodes into an absolutely positioned `.page-leaving` layer on `<html>` (absolute, not fixed, so it also paints under the bars) that fades out over the arriving page on the same 240ms curve, while only icons and titles are snapshots. The garland lives as long as its page: it lets go once it leaves the document (on iPhone, after the page being left has faded out). After a swap, icons switch from lazy to eager so cached ones paint in the first frame. Reduced motion keeps the cross-fade and drops the travel
- Navigation speed: internal links use the canonical trailing-slash URL (production redirects `/work/pool` to `/work/pool/`). `navigation.ts` prefetches visible internal links with the same `fetch()` the router sends (Astro's prefetch is off: its `<link rel="prefetch">` sends a navigation `Accept`, which `Vary: Accept` keeps apart from the router's request), and pages are fresh for 5 minutes (`public/_headers`), so a tap or a back press usually swaps from cache. Heavy page setup awaits `transitionEnd()` from `navigation.ts` so it stays out of the transition (the garland does, unless it is in view)
- Intro reveal plays once per session (`sessionStorage`), gated on `prefers-reduced-motion`
- Hover states only under `(hover: hover) and (pointer: fine)`; 44px tap targets on touch. No system tap highlight (`-webkit-tap-highlight-color: transparent` on `html`): every link has its own `:active` state instead (rows and the back link take `--pressed`, text links brighten)
- Client JavaScript is limited to the photo pile (shuffle and orb), the garland's wind, and the navigation glue in `src/scripts/navigation.ts` (morph names, compositor morph, prefetch, the detail page's back link, `transitionEnd()`). The one third-party script is Cloudflare Web Analytics (cookieless, no consent banner needed)
- Copy style: no period at the end of a paragraph or summary; no em dashes (commas, colons or parentheses instead; en dashes with spaces for ranges like `Feb 2026 – now`)
- Section titles are body-size Inter at weight 500 (no mono, no uppercase); dates are 13px tabular labels on the right of each row, years only on the index (`years()` in index.astro), full periods on detail pages

### Agent readiness
- `public/robots.txt` declares Content Signals (`search=yes, ai-input=yes, ai-train=yes`) and names the AI crawlers; `public/_headers` repeats the signal as a response header and adds `Link` headers to `/llms.txt` and the sitemap
- `src/data/markdown.ts` builds Markdown twins from the same collections: `/llms.txt`, `/index.md`, and `/<category>/<slug>/index.md` (endpoints under `src/pages/`); each HTML page links its twin with `<link rel="alternate" type="text/markdown">`
- `worker/negotiate.ts` (called from the `worker/index.ts` entry) answers `Accept: text/markdown` on page paths with the twin (a direct `…/index.md` request passes straight through) and hands every other request to static assets untouched; `worker/accept.ts` parses Accept per RFC 9110. `wrangler.jsonc` routes only `/`, `/work/*`, `/projects/*`, `/speaking/*` through it, and `public/_headers` sets `Vary: Accept` on both variants plus a UTF-8 charset on `.md` and `.txt`, so the Worker returns asset responses as they are and never builds its own. `workers_dev` is off: production is served from ertembiyik.com only, with preview URLs kept for pull requests. The Worker has its own `worker/tsconfig.json` against types from `wrangler types` (generated by `bun run check`, not committed) and is covered by `bun test`. `negotiate.ts` and `accept.ts` use only web-standard globals, so the tests type-check against Bun's types (`worker/tsconfig.test.json`) with no casts
- The home page carries a schema.org `Person` JSON-LD block
- Lighthouse's Agentic Browsing category keys off the accessibility tree: keep ARIA attributes on elements with a valid role, and keep text at 4.5:1 (`--text-3` is the floor)
